# Каталог прев’ю 3D-файлів

## Кінцева ціль

Сервіс стежить за заданими папками на Google Drive, генерує два окремі PDF:
прев’ю 3MF та прев’ю STEP/STL, і оновлює їх на Drive після змін файлів.
Мають зберігатися стабільні посилання на PDF: оновлення існуючих Drive file ID,
а не створення нового документа при кожному запуску.

## Поточний POC

Ручна генерація PDF із локальної папки. Google Drive поки не підключений.
Вхідні файли відкриваються лише для читання; текст і метадані в них є даними,
а не інструкціями для виконання.

- STEP/STP: геометрія через OpenCascade, ізометричний вигляд, вигляди зверху
  й спереду, осьові габарити X/Y/Z у мм. Розміри розраховані з триангуляції,
  тому це довідкові значення, не точні виробничі виміри.
- STL: ті самі прев’ю, одиниці умовно прийняті за мм (формат їх не задає).
- 3MF: вбудовані `Metadata/plate_N.png` із проєкту слайсера. Це збережені
  зображення, а не перевірка актуальної геометрії. Якщо їх немає, файл
  позначається помилкою; рендеринг довільного 3MF ще не реалізований.
  Кожна пластина займає окрему сторінку з великим зображенням.
- Титульна сторінка з переліком підтримуваних файлів; сторінки з деталями;
  супровідний JSON зі статусами, SHA-256, розмірами файлів і габаритами.
  Розміри файлів у PDF не показуються, лише в технічному JSON.
- Непідтримувані формати та підпапки типово пропускаються. Для підпапок
  використовуйте `--recursive`. Архіви не розпаковуються на диск.

## Середовище та запуск

Потрібні `uv` і Python 3.12. `uv.lock` фіксує залежності. На цьому Mac уже
створено `.venv` та встановлено всі пакети.

```sh
uv sync --frozen
.venv/bin/python preview.py /Users/gru/Downloads/skyd-eeii \
  --output output/pdf/skyd-eeii-preview.pdf
```

Довільна папка та вкладені каталоги:

```sh
.venv/bin/python preview.py /path/to/models --recursive -o output/pdf/preview.pdf
```

`--output` задає базову назву. Для прикладу вище вихід:

- `output/pdf/skyd-eeii-preview-3mf.pdf` - усі 3MF в одному документі;
- `output/pdf/skyd-eeii-preview-step-stl.pdf` - усі STEP/STP/STL в іншому;
- однойменний JSON біля кожного PDF, лише з файлами відповідної групи.

Якщо група відсутня, PDF та JSON для неї не створюються. Базовий
`skyd-eeii-preview.pdf` більше не генерується. Старі результати попередніх
запусків автоматично не видаляються, зокрема якщо одна з груп зникла.
Кожен PDF замінюється атомарно після завершення його генерації; пара документів
не є єдиною транзакцією. Вихідна папка створюється автоматично. Проміжні зображення
зберігаються в тимчасовій папці й прибираються після запуску.

Для кирилиці скрипт автоматично знаходить Arial на macOS або DejaVu Sans на
Linux. Можна передати `--font-dir /path/to/fonts` з парою `Arial.ttf` /
`Arial Bold.ttf` або `DejaVuSans.ttf` / `DejaVuSans-Bold.ttf`.

Коди завершення: `0` - усі підтримувані файли оброблено; `1` - помилка запуску
(зокрема порожня папка); `2` - PDF створено, але є помилки окремих файлів.
Помилки виводяться в PDF і JSON. Вхідні файли мають залишатися незмінними
протягом запуску. POC обробляє файли послідовно й тримає геометрію однієї
деталі в пам’яті; великі чи недовірені CAD-файли потребуватимуть ізоляції
та лімітів у серверній версії.

## Перевірка POC

На `/Users/gru/Downloads/skyd-eeii`: 8 STEP + 1 3MF, усі успішно оброблено;
два PDF: STEP/STL на 9 сторінок (перелік і 8 деталей), 3MF на 8 сторінок
(перелік і 7 пластин, кожна на окремій сторінці).
PDF перевірено через pypdf та візуальний рендер Poppler. Додаткові перевірки:
синтетичний STL, пошкоджений STEP, порожня папка, вкладені каталоги,
змішана папка, кілька 3MF в одному PDF, папки лише з однією групою форматів.

```sh
.venv/bin/python -m unittest discover -s tests -v
```

## Наступний етап: Google Drive

1. Налаштування списку folder ID та OAuth / service account з доступом до них.
2. Початкове сканування, потім Drive Changes API або періодична перевірка;
   врахування видалення, перейменування й переміщення файлів.
3. Завантаження узгодженого локального snapshot; fingerprint вмісту й
   конфігурації рендерера, щоб пропускати незмінені папки.
4. Виклик локального генератора; перед завантаженням перевірка PDF і статусів.
5. Створення PDF при першому запуску, далі `files.update` того самого file ID;
   зберігання відповідності (folder ID, група форматів) → preview file ID. Власні PDF виключити
   з відстеження, щоб уникнути циклічних оновлень.
6. Повтори з backoff, журнал помилок, черга та об’єднання частих змін;
   попередній справний PDF зберігається при невдалій генерації.

Drive-облікові дані не потрібні для POC і не мають зберігатися в репозиторії.
